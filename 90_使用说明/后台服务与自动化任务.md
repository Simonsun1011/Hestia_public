# 后台服务与自动化任务

这些工作平时不会一直出现在前台，但它们决定了工作台是否能长期自己收口。本文先说清楚“有哪些任务”，再说“拿到清洁版后哪些已经启用”。

## 先记住三种工作

| 类型 | 什么时候发生 | 例子 | 是否需要定时器 |
|---|---|---|---|
| 常驻服务 | Mac 登录后保持可用 | 让 Safari Web App 随时能打开本机工作台 | 否，但可用登录项启动 |
| Agent 事件工作 | 用户发起任务、Agent 完成阶段工作时 | 自动登记任务、回写状态、留项目工作日志 | 否 |
| 周期任务 | 按日、周、月或到期条件运行 | 每日日志收口、金融简报、续费检查 | 是 |

复制 `Infans_Studio` 文件夹不会自动改动对方的 Mac 登录项。因此，清洁版交付的是界面、原件结构、Agent 规则和启用方法；实际后台任务必须在朋友自己的 Mac 上逐项检查后启用。这是本机安全边界，不是功能缺失。

## MCP 不是定时任务，也不会随包安装

Infans 只读 MCP 是一个可选的本机读取服务：它让手机 GPT / GPT Live 在获得授权后按需读取部分 Studio 原件，但本身不负责每天跑日志，也不负责写回。清洁版只提供 [[外部AI只读MCP与手机工作流]] 的搭建与验收方法，不附带已经安装的插件、外网入口、账号、密钥或原作者配置。

需要这项能力时，应由新拥有者在自己的 Mac 上另建 MCP 工程，设置明确的目录白名单，只开放搜索和读取，再分别验证文字读取、手机端调用、GPT Live 上下文继承与断开连接后的失效。正式写回仍由本地 AI Agent 完成，不能让手机端把“生成了答案”说成“已经修改 Studio”。

## 建议的后台任务清单

下列时间是首次配置的建议值，可以按作息调整。在没有完成安装与自然触发验证前，异常雷达里看到的状态只是假数据示例。

| 任务 | 建议触发 | 会做什么 | 不会做什么 | 默认建议 |
|---|---|---|---|---|
| 工作台本机服务 | Mac 登录时 | 启动本地服务，为 Mac Web App 和手机私有访问提供界面 | 不公开上网，不代替私人网络和 HTTPS | 长期使用时启用 |
| 每日日志收口 | 每天凌晨或第二天早上 | 读取已经落盘的项目工作日志、状态和验证结果，生成当日跨项目收口或缺口提醒 | 不猜测没有记录的工作，不偷读聊天，不自动伪造日记 | 推荐启用 |
| 项目状态索引 | 每天 09:00 | 根据各项目原件刷新事业页、今日事项和关系索引 | 不创造新项目事实，不把派生卡片反写成原件 | 推荐启用 |
| AI 验收与到期复查 | 定期轻量扫描 | 只唤醒已绑定执行器、已到期的 `AI·` 任务，完成后回写证据 | 不会替拥有者做主观验收，不扫描所有文件后自行扩项 | 用熟项目治理后再启用 |
| 金融资讯简报 | 每天固定时间 | 读取公开来源，更新当前简报并保留历史 | 不读券商、银行或真实持仓，不下单 | 需配置公开来源后启用 |
| Anki 快照 | 每天早上 | 在已安装 AnkiConnect 时记录近期复习和牌组摘要 | 连接失败时不用空数据覆盖旧快照 | 学日语时按需启用 |
| 东京活动采集 | 每周一 07:00（「实用工具 · 设置」可改） | 工作台自带：按 `活动来源.md` 抓官方页面，Haiku 摘录，脚本核对后并入日本活动卡 | 不登录任何账号；攻略只在点「生成攻略」时才做 | 已内置，工作台开着即按时运行 |
| 价格追踪 | 每天 09:00（「实用工具 · 设置」可改） | 工作台自带：抓日亚、楽天、Yahoo! 的商品页与搜索页，记录价格，每天给一次买不买的建议 | 不下单、不登录购物账号 | 已内置，没有登记商品时不花额度 |
| 事业项目周复盘 | 每周日 | 汇总本周进展、受阻、待验收和下周关键一步 | 不另建一套项目事实，不将计划写成完成 | 推荐启用 |
| 续费与资格到期检查 | 每天扫描，有变化才提醒 | 根据本地登记的到期日显示即将到期、已过期和已处理 | 不自动续费，不保存卡号、验证码或密码 | 推荐启用 |
| 账号与账单复核 | 每月末检查一次 | 生成当月待人工确认的清单 | 不登录账号，不自动付款，不读取完整卡号 | 只做提醒 |
| 资产月末盘点 | 每月末或自定日期 | 创建待盘点事项，读取本机已确认的数据后刷新图表 | 不自动读取银行或券商，不会凭行情猜测真实资产 | 只做提醒与汇总 |
| 月度回顾 | 每月 1 日 | 从已确认的日志、项目和学习记录生成上月草稿 | 不编造缺失数据，不自动对个人状态下结论 | 开始真实使用后启用 |

## 每天自动跑日志，到底跑什么

日志自动化应该分为两段：

1. 每个 Agent 完成实际工作时，立即在所属项目留下工作日志，并回写任务状态、验证结果、阻塞和下一步。这是事件触发，不用等到晚上。
2. 每日收口任务只读取上述已落盘事实，把当天跨项目进展汇总到当日日志，或明确记录“今日没有新的可核验事实”。

日记、对话日志和项目工作日志仍然是三种不同的原件：

- 项目工作日志可以由 Agent 自动写。
- 整天日志可以由一个固定的单写 Agent 自动汇总。
- 日记和对话日志涉及生活、感受与原话，只在用户主动提供材料或明确进入日记模式时归档，不安排“每晚偷读聊天”的后台任务。

## 首次启用的正确顺序

1. 先用终端手动启动工作台，确认首页、原件读取、项目回写和构建正常。
2. 把 Studio 根目录交给本地 AI Agent，让它先读 `AGENTS.md` 和本文。
3. 只安装“工作台本机服务”，重启 Mac 后确认 Web App 仍能打开。
4. 启用“每日日志收口”和“项目状态索引”，手动试跑一次，再等一次真实定时触发。
5. 项目管理稳定后，再按需启用金融简报、Anki、日本活动、续费检查和月度回顾。
6. 需要账号、密钥、公网来源或外部项目的任务，由拥有者逐项决定；未配置时保持关闭。

可以直接对本地 Agent 说：

> 请先读 `AGENTS.md` 和 `90_使用说明/后台服务与自动化任务.md`，检查这台 Mac 的 Node、pnpm、工作台端口和当前原件。先只为我制作工作台登录启动和每日日志收口方案，把将要新建的 LaunchAgent、执行时间、读写路径和日志路径先给我审核；不启用其他外部连接。

## Mac 上怎样承载

长期使用建议用 macOS `launchd` 管理，不依赖终端窗口长期开着：

- 本地服务使用“登录后启动 + 异常退出后重启”。
- 周期任务使用日历时间触发，每项任务单独命名、单独写运行日志。
- 任务脚本使用对方 Mac 当前的绝对路径，不把原作者目录、用户名、主机名或网络地址写进模板。
- 密钥放在 macOS 钥匙串或本场私有环境中，不进 Git、Markdown、命令截图或自动化日志。
- 执行器必须防重：同一个日期或周期多次触发时，应读取已有结果并安全退出，不重复生成两份原件。

清洁版不附带原作者的 LaunchAgent、任务标签、绝对路径、模型绑定、账号、密钥和运行日志。新 Mac 上安装后，必须分别验证“脚本手动执行”和“定时器自然触发”，只验证其一不算完成。

## 怎样看见后台做了什么

一项合格的自动化必须同时提供：

- 上次启动时间、上次成功或失败、下次计划时间。
- 本次使用的原料有效到哪一天。
- 写入了哪份原件或只刷新了哪份派生数据。
- 如果没跑，是没有启用、条件不足、Mac 休眠、外部来源失效，还是 Agent 执行失败。
- 一个可审查的本地运行日志；日志可以记路径、状态码和摘要，不记密钥、完整账号、私人原文和身份资料。

前台入口是“实用工具 → 异常雷达”。它应该用来看运行状态、缺少条件和待人工处理事项，而不是轻率地把所有黄色或红色都当作同一种故障。

## 哪些不设为自动任务

- 备份：朋友没有 NAS，本包只记录 Time Machine 或手动复制方法，不安装定时备份。
- 日记和私人对话抓取：必须由用户主动提供或授权当次归档。
- 交易、付款、续费、对外发布和发送消息：后台可以提醒和生成待审草稿，不自动执行。
- 真实资产余额、银行卡和券商持仓同步：本包不提供账号连接，默认继续使用假数据。
- 健康设备同步：朋友当前只有 Mac，不默认配置 iPhone、Apple Watch 或 HealthKit 任务。

## 失败时怎样排查

1. 先手动打开工作台：页面都打不开，先查本地服务；页面能打开但数据旧，再查具体周期任务。
2. 在异常雷达里查“未安装、待运行、条件不足、执行失败”中的哪一种，不只看颜色。
3. 打开对应本地运行日志，确认脚本是否启动、读了什么、写到哪里。
4. 手动试跑同一任务；手动成功只能证明脚本可用，还要等一次自然触发才能证明定时链路可用。
5. 任务失败时保留上一份有效结果，不用空数据或半截内容覆盖。
