# 外部 AI 只读 MCP 与手机工作流

## 它解决什么问题

手机上的 GPT 或 GPT Live 默认看不到 Mac 中的 Infans Studio。可以在 Mac 上另建一个只读 MCP 服务，再把它作为私人插件连接到允许使用 MCP 的 AI 客户端。

它的目标是让外部 AI 按需搜索和读取本地资料，而不是把整个 Studio 上传到新的云端数据库，也不是让手机直接修改本地文件。

## 推荐能力

第一版保持很小，只提供：

- 列出允许范围内的目录。
- 按关键词搜索，并返回相对路径与少量命中片段。
- 按相对路径分段读取文件。
- 查看文件类型、大小与更新时间，不读取正文。
- 返回连接与安全复查状态，不返回凭据。
- 可选：为日语或专题学习准备真实节点与必要协议。

所有工具都应声明只读、非破坏、不开放任意命令。

## 必须由服务端保证的边界

- 不注册创建、修改、移动、删除、重命名或命令执行工具。
- 所有路径规范化后必须仍在允许的 Studio 根目录内。
- 拒绝绝对路径、`..`、符号链接逃逸、版本库内部文件、依赖目录、构建产物、缓存和凭据文件。
- 搜索与单次读取设置条数和字符上限，不提供“一次导出全部资料”。
- 日志只记录时间、工具名、相对路径、成功或拒绝、返回大小与耗时；不记录正文、完整搜索词和凭据。
- 远程连接使用独立身份验证、最小权限与可撤销凭据；凭据不进入 Studio、提示词、截图和交接。
- Mac 停止 MCP 服务或断开私人连接后，远端应立即无法继续读取。

## 手机 GPT Live 的标准路径

1. 在手机 GPT 的目标聊天里明确要求使用 Infans 只读资料。
2. 先让 GPT 读取当次协议和必要原件，并报告实际来源与没有读到的内容。
3. 确认真正出现了工具调用与来源；只有口头说“我看过了”不算。
4. 在同一个聊天中进入 GPT Live，让语音会话继承刚才读到的上下文。
5. 结束时输出固定交接，并明确“尚未写入 Infans Studio”。
6. 把完整对话或交接交给 Mac 上的本地 AI Agent。
7. 本地 Agent 去重、核验、预览并按所属模块受控写回。

## 三种典型用法

### 日记模式

先读日记模式协议、近期日记、当前项目状态和临近日程；只带入少量仍值得聊的线索。Live 结束后保存原始对话顺序，AI 推断与用户事实分开。

### 日语学习

先读目标教材、当前学习节点和上次错题，再开始口语或文法练习。结束交接包含节点、练习内容、错误、自测和下次复习；聊天时长不直接算掌握。

### 专题学习

先从真实知识地图选择唯一节点，再围绕它讲解。读不到节点或来源时先停下选择，不自行发明一套目录。

## 为什么坚持“只读 + 本地写回”

- 手机聊天再方便，也不会成为第二个业务数据库。
- 外部 AI 被替换后，项目、日记和学习记录仍在原位置。
- 写入只有一个本地 Agent 负责，更容易去重、校验冲突和回滚。
- 远端连接失效时，Studio 本身仍可正常使用。

## 需要另外准备的支持项

- 一个独立的 MCP 工程，建议放在同级 `Infans_Support/20_项目支持/`，不要塞进知识库正文。
- 明确的只读目录白名单与强制排除表。
- AI 客户端的私人插件或 MCP 连接配置。
- 独立认证、凭据撤销与定期安全复查方法。
- 本地审计目录，放在 Studio 和分享包之外。
- 日记、日语与专题学习各自的固定交接格式。

清洁版只提供方法，不附带已经连接某个账号、设备或私人目录的配置。每位拥有者都要根据自己的客户端、网络和资料范围重新搭建与验收。

## 最小验收

1. 搜索和分段读取能返回真实相对路径。
2. 创建、修改、删除和命令请求全部被能力层拒绝。
3. 路径逃逸、被排除目录和秘密文件无法读取。
4. 调用前后 Studio 文件没有因 MCP 发生变化。
5. 手机文字聊天能真实读取，同一聊天进入 Live 后能使用该上下文。
6. Live 只输出“待交接”，本地 Agent 能去重并写回正确原件。
7. 日记、学习进度、项目任务和日志不会互相写错位置。

不要把“本机 MCP 测试通过”当成“手机整条链路已经可用”；文字读取、GPT Live 继承、交接完整性与本地写回要分别验证。
