# 项目治理与新项目接入

## 先看结论：用户只说需求，Agent 负责结构

用户通常只需要说：“继续月蔷薇洋装的新品发布，先把 Lookbook 和直播联动做完，页面样式不要改。”

用户不需要先查 ID，也不需要手动编辑治理文件。AI Agent 应自己完成：找项目、识别旧任务或新任务、读取功能 Wiki、登记关系、执行、验证、回写状态和留下日志。

## 五个治理对象

| 对象 | 主要问题 | 唯一原件 | 在工作台哪里看 |
|---|---|---|---|
| 事业项目 | 整项事业现在怎样 | `项目进度与待办.md` | 事业顺利 → 项目主页 |
| 产品功能 | 产品有什么、成熟到哪一步 | `产品功能树.md` | 项目主页 → 功能 Wiki |
| 今日事项 | 今天先做什么 | 项目任务与中央事项的派生结果 | 日程安排 → 今日事项 |
| 主线进度 | 中长期走到哪里 | 项目里程碑与主线原件 | 日程安排 → 主线进度 |
| 限时大作战 | 短期集中火力怎样编排 | 所属项目 `项目进度与待办.md` | 事业页、项目主页与主线派生视图 |

日程不是第二套待办，功能 Wiki 也不是第二套任务。五个页面读取同一组事实，只是观察角度不同。

## 项目、任务和功能的状态

### 项目整体

常见状态是候选、筹备中、进行中、稳定运营、受阻、暂停、等待验收、完成和归档。不同项目可以使用更自然的显示文案，但不能把“准备做”写成“已经完成”。

### 任务执行

| 状态 | 含义 | Agent 下一步 |
|---|---|---|
| 下一步 | 已登记，尚未开工 | 等待时机或依赖 |
| 正在做 | 已授权并开始推进 | 执行、验证、持续回写 |
| 受阻 | 缺少条件、权限或需要取舍 | 先自行诊断；无法继续才升级给拥有者 |
| 待验收 | 已形成结果，需要人判断 | 建立独立验收事项，说明只需要看什么 |
| 已完成 | 完成门和必要证据已满足 | 写入最近完成并保留来源 |

### 功能成熟度

功能 Wiki 固定使用：稳定、待开发、设计中、开发中、测试中、待验收、已暂停。功能状态描述产品能力是否成熟，不能用一条任务完成直接替代。

## 一次需求的完整流转

1. Agent 从 `事业顺利_总览.md` 找到项目。
2. 读取项目 `项目进度与待办.md`，确认当前状态、正在做、下一步、阻塞和最近完成。
3. 读取 `产品功能树.md`，判断需求属于哪些模块和功能。
4. 已有任务就沿用原任务；新需求就建立一条新任务。换对话、换 Agent、跨天、返工都不重复开项。
5. 新任务自动登记功能范围、依赖、父任务或跨项目关联；用户不需要看到这些内部字段才能使用。
6. 在授权范围内执行。高风险外部动作仍在真正执行前确认。
7. 能自行验证的，Agent 运行检查并记录证据；需要主观判断的，建立待验收事项。
8. 遇到普通故障先修复、复验；真正缺条件时登记“阻塞待拥有者”，只提出一个明确问题。
9. 先更新工程、设计、正文或数据事实，再回写项目短状态、完成、阻塞和下一步。
10. 工作台刷新后，事业页、今日事项、主线和功能 Wiki自动读取新状态。

## 关系网怎样工作

内部关系使用全局稳定 ID，但这是 Agent 的维护职责，不是用户的操作负担。

- `父级`：这条任务属于哪个更大的任务。
- `依赖`：必须先完成什么才能继续。
- `关联任务`：存在协作关系，但不代表先后顺序。
- `功能`：这条任务影响哪些产品功能。
- `工作线`：这条任务属于哪条业务或产品工作线。

一条任务可以关联多个功能，一项功能也可以关联多条任务；阻塞和最近完成也可以同时服务多条任务。这就是“多对多映射”。跨项目协作只引用对方的任务 ID，不复制对方任务正文。

清洁版已经提供一组网状示例：

- 月蔷薇洋装的新品发布依赖样衣定版。
- 白鸢直播间的新品直播关联月蔷薇的发布任务。
- 糖霜庭院的联名茶歇同时关联服装发布和农场香草交付。
- 晨露农场的香草订单又反向服务甜品菜单。
- 小秘书的演示项目验收同时关联上述四个项目，用来检查关系网是否显示完整。

## 限时大作战

限时大作战适合新品发布周、突然增加的展会准备、开店试营业或直播活动周。它不是第六种任务，也不复制任务正文。

一场大作战至少包含：名称、起止日期、总目标、阶段、真实任务、关联功能、依赖、交付物、完成门和门状态。阶段进度从被引用任务与完成门派生；完成或取消后退出顶部，但原件和复盘保留。

## 新项目怎样创建

当用户明确说“把这件事作为一个长期项目管理”时，Agent 可以自动完成最小接入：

```text
30_事业顺利/项目名/
├── 项目名_总览.md
├── 项目进度与待办.md
├── 产品功能树.md          # 产品型项目需要；纯事务项目可不建
├── 20_记录/              # 有持续工作日志时再建
└── 30_证据/              # 有正式验收证据时再建
```

接着由 Agent：

1. 生成稳定项目 ID 和一句话卡片简介。
2. 在事业注册表登记项目。
3. 建立当前状态、正在做、下一步、阻塞、最近完成和权威入口。
4. 只预建当前真正需要的工作线和功能，不为格式制造空目录。
5. 登记第一批真实任务、依赖和关系。
6. 刷新工作台并检查项目主页、功能 Wiki 和今日事项。

只有想法但尚未决定长期投入时，先留作候选或备忘，不急着建立项目。

## 外部工程怎样接入

项目工程可以放在 Studio 外。Studio 只维护项目管理原件，外部工程用 `.infans/project-hub.v1.json` 暴露安全的项目名、工作线、功能树和相对来源。

本机 `project-sources.local.json` 登记实际路径并保持不分享。Agent 仍以同一个项目 ID 串起 Studio 项目、外部工程、任务与功能；源码不需要复制进 Studio。

## GPT 与 AI Agent 的分工

- GPT / GPT Live：适合发散、访谈、商业设想、文案、日语口语和专题讲解。
- 本地 AI Agent：适合读取原件、登记任务、建立关系、修改工程、核验来源、运行检查、写日志与受控回写。
- 项目拥有者：确认方向、敏感信息、高风险外部动作和主观验收。

平台可以替换，项目原件不能跟着平台漂移。换一个 Agent 后，新的 Agent 只要读本文件、项目原件和功能 Wiki，就应该能够接着推进。
