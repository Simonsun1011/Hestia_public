# Infans 私人秘书使用说明

这份说明先回答两个问题：拿到以后先做什么，以及平时怎样把它真正用起来。Infans Studio 不是一个需要把所有资料都塞进去的数据库，而是用少量稳定原件，把项目、日程、学习、日志、资产和资料组织成一个每天可看的工作台。

## 一、拿到以后先做什么

### 1. 保持两个目录同级

```text
Infans秘书清洁版/
├── Infans_Studio/
└── Infans_Support/
```

不要只移动 Studio 而留下 Support。动漫封面、本地音乐和较大的支持素材从同级 Support 读取。

### 2. 准备 Mac 环境

需要：

- macOS、Safari 和终端。
- Node.js 22.13 或更高版本。
- pnpm。
- 可选：Obsidian，用来直接打开 Markdown 原件。
- 推荐：能直接读取本地项目的 AI Agent，用来修改工程、核验原件、自动登记进度和运行检查。

在终端确认：

```bash
node -v
pnpm -v
```

### 3. 安装并启动

```bash
cd Infans_Studio/00_本地工作台/app
pnpm install
pnpm dev
```

打开 `http://127.0.0.1:4178/`。第一次先不要改数据，依次查看首页、事业顺利、日本活动、游戏、动漫、资产折线图和实用工具。页面右上角的 `DEMO` 表示目前都是演示数据。

### 4. 先做一份备份

开始写自己的资料前，把 `Infans_Studio` 和 `Infans_Support` 一起复制一份。不要先填真实资产或身份资料再考虑备份与分享边界。

### 5. 决定自己的使用层级

- 只观看框架：保留全部假数据，不需要 AI Agent 或 Obsidian。
- 开始管理项目：先替换一个演示项目，再确认事业页和日程读取正常。
- 开始长期使用：配置 Obsidian、AI Agent、备份，以及外部项目接入。
- 手机使用：先完成 Mac 服务和私有网络访问，再添加到主屏幕。

### 6. 决定哪些后台任务要启用

清洁版带有自动化的界面、原件结构和配置方法，但不会在另一台 Mac 上偷偷安装登录项。首次启动正常后，读 [[后台服务与自动化任务]]，先配工作台常驻服务和每日日志收口，其他任务再逐项启用。

## 二、界面上最重要的几个操作

- 左上角的秘书名（清洁版显示为 `Infans Studio`）：从任何页面回到首页；已经在首页时，点击会回到页面顶部。
- 左下角或手机“更多”里的月亮/太阳：切换玄夜与晴岚主题。
- 两个主题按钮中间的圆圈：重新读取首页摘要和当前模块数据。它只刷新派生视图，不会替你修改 Markdown 原件。
- 侧栏：Mac 上显示十个一级入口；手机上常用入口在底部，其余入口收进“更多”。
- 原件链接：安装 Obsidian 并把资料库命名为 `Infans_Studio` 后，可以从页面跳到对应 Markdown。没有 Obsidian 也不影响浏览。
- `DEMO`：提醒当前为清洁演示状态。真正开始填个人数据后，也建议保留自己的“本机/演示”标识，避免截图时混淆。

刷新圆圈适合“我刚让 AI Agent 改完原件，页面还没更新”的情况；浏览器强制刷新只在前端文件更新或页面卡死时使用。

## 三、像 App 一样在 Mac 使用

### 推荐：Safari Web App

1. 先确保 `pnpm dev` 正在运行。
2. 用 Safari 打开 `http://127.0.0.1:4178/`。
3. 在 Safari 的“文件”菜单选择“添加到程序坞”，命名为 `Infans Studio`。
4. 以后从程序坞打开，它会使用独立窗口，不和普通网页标签混在一起。
5. 进入一次全屏（窗口左上角绿色按钮，或 `Control + Command + F`）。macOS 通常会记住该 App 的窗口状态。

Web App 只是入口，后台服务仍要先启动。清洁版不预装原作者的登录项或定时任务；朋友可按 [[后台服务与自动化任务]] 在自己的 Mac 上安全启用。

### 如果希望一键启动并自动全屏

可以用 macOS“快捷指令”或 Automator 组合三个步骤：

1. 在 `00_本地工作台/app` 启动 `pnpm dev`。
2. 等待本机地址可访问，再打开已添加到程序坞的 `Infans Studio`。
3. 向该 App 发送 `Control + Command + F`。

第三步需要在“系统设置 → 隐私与安全性 → 辅助功能”里允许快捷指令或 Automator 控制界面。先手动验证，再决定是否加到登录项；不要把未经验证的启动器设成开机自动运行。

## 四、在 iPhone Safari 添加到主屏幕

手机不能直接访问 Mac 的 `127.0.0.1`。先选择一种连接方式：

- 同一可信 Wi-Fi 临时使用：Mac 运行 `pnpm run dev:lan`，手机访问 `http://Mac 的局域网地址:4178/`。
- 长期使用：Mac 和 iPhone 接入同一套私人网络，再为本机服务配置私有 HTTPS 地址。工具按拥有者自己的设备与安全条件选择，不需要 NAS。

连接成功后：

1. 在 iPhone Safari 打开工作台地址。
2. 点击“共享”。
3. 选择“添加到主屏幕”。
4. 如果系统显示“作为 Web App 打开”，保持开启。
5. 从主屏幕图标重新进入，检查顶部安全区、底部导航、主题和刷新圆圈。

最佳体验要求 Mac 保持开机、服务仍在运行、手机能访问同一私有网络。清洁版没有离线缓存，断开 Mac 后主屏幕图标不会变成独立离线应用。

## 五、先理解五个治理视角

这套系统并不是把同一批待办换五种样子显示。五个入口分别解决不同问题：

| 入口 | 人真正关心的问题 | 主要内容 |
|---|---|---|
| 事业项目 | 这项事业整体进展怎样？ | 项目阶段、当前状态、正在做、下一步、阻塞、最近完成 |
| 功能 Wiki | 这个产品到底有什么，哪些功能成熟？ | 模块、功能点、功能状态、设计与真实任务关系 |
| 今日事项 | 今天最值得做什么？ | 进入近两日窗口的任务、S/A/B/C 优先级、待本人验收 |
| 主线进度 | 这件事长期走到哪里了？ | 跨周或跨月的阶段、里程碑与依赖 |
| 限时大作战 | 突然出现一件必须集中火力完成的事怎么办？ | 明确期限、阶段节点、完成门、真实任务与功能引用 |

一句话总结：项目、任务、功能、主线和大作战各自只保存自己的事实，再由 AI Agent 在内部用稳定 ID 建立多对多关系。一个任务可以关联多个功能，一项功能也可以被多条任务、阻塞和完成记录引用；用户不需要记这些 ID。

### 页面中会看到哪些状态

项目整体常见状态包括筹备中、进行中、稳定运营、受阻、暂停、等待验收、完成和归档。项目可以用更符合自身业务的文案，但必须表达当前事实。

任务在项目里主要经过五个位置：

1. 下一步：已经登记，尚未开工。
2. 正在做：已获得执行授权并实际推进。
3. 受阻：缺少外部条件、权限或需要拥有者取舍。
4. 待验收：AI 已形成结果，但还需要人判断观感、手感、内容口径或现实效果。
5. 已完成：完成条件与必要证据已经满足。

功能 Wiki 使用另一套成熟度状态：稳定、待开发、设计中、开发中、测试中、待验收和已暂停。项目状态、任务状态和功能状态不能互相替代。

## 六、每天怎么用

### 早上：先决定今天做什么

1. 首页看近两日日程、待处理事项、重点项目、学习和市场摘要。
2. 进入“日程安排 → 今日事项”，确认今天真正要做什么。
3. 需要了解长期位置时再看“主线进度”；不要早上就翻完整文件夹。

### 做事前：先看项目，再把需求告诉 Agent

1. 进入“事业顺利”，选择准备推进的项目。
2. 先看项目当前状态，再看“正在做、下一步、阻塞”和每条任务的当前状态。
3. 需要了解产品范围时进入“功能 Wiki”，看看这项需求属于哪个模块和功能。
4. 回到本地 AI Agent，直接用自然语言说出需求，例如：“继续月蔷薇洋装的秋季样衣任务，版面不要改，做完让我验收。”

不需要把项目 ID、任务 ID 或文件路径抄给 Agent。合格的 Agent 应自行读取 `AGENTS.md`、事业注册表、项目原件和功能 Wiki。

### Agent 接到需求后会怎样

- 已有任务：找到并沿用原任务，读取前情、依赖、关联功能和完成条件，再继续推进。
- 新任务：在实际施工前自动登记到所属项目，并连接相关功能、依赖或跨项目任务。
- 新项目：当用户明确要把新方向作为长期事业推进时，Agent 自动建立最小项目目录、产品功能树和第一批真实任务，再登记到“事业顺利”。
- 可以自行验收：Agent 运行检查、回读结果，并自动写回技术证据和完成状态。
- 需要本人验收：Agent 生成一条独立验收事项，说明只需要看什么；它会出现在今日事项里，技术通过不会冒充本人满意。
- 遇到普通故障：Agent 先在授权范围内诊断、修复和复验，不立即把问题丢回用户。
- 真正受阻：Agent 保留原任务，登记“阻塞待拥有者”，写清已经尝试什么、风险是什么，以及唯一需要决定的问题。
- 需要以后复查：Agent 建立关联后续任务，不把“以后再看”只留在聊天里。

### 这套方式方便在哪里

- 开工自动注册：用户只说需求，Agent 负责找到旧任务或建立新任务。
- 过程不断链：换对话、换 Agent、隔天继续或返工，都沿用同一任务关系。
- 结束自动回写：工程事实、项目状态、阻塞、完成和下一步会回到项目原件。
- 多页面自动同步：刷新后，事业页、今日事项、主线、Wiki 和大作战读取同一份事实。
- 接班不依赖旧聊天：新的 Agent 先读项目原件就能继续，不必翻完所有历史对话。

### 做事中：事实落在所属项目

- 服装样衣结论写回月蔷薇洋装。
- 直播选题和复盘写回白鸢直播间。
- 甜品配方、菜单与试营业写回糖霜庭院。
- 农资、种植、库存与销售写回晨露农场。

日程只负责“什么时候做”，事业项目负责“项目现在是什么状态”，功能 Wiki 负责“产品有什么能力”。同一个结论只维护一次。

### 做完：Agent 自动收口，用户只处理需要判断的部分

Agent 应先写实际工程、设计或内容结果，再自动更新项目进度与项目工作日志。需要用户主观判断时，用户只需打开验收事项，实际看一眼并反馈“通过”或指出问题；Agent 再沿用原任务收口或返工。

## 七、平时看不见的后台与自动化

自动化不只是“每天跑一次脚本”。它包括三层：

1. Mac 登录后启动工作台本机服务，让 Safari Web App 不用先开终端。
2. Agent 接任务后自动登记，做完后自动回写项目状态、验证结果和项目工作日志。
3. 按日、周、月运行的周期任务：每日日志收口、项目索引、金融简报、日本活动、项目周复盘、续费与账单检查、月度回顾。

每日日志收口只汇总已经写入项目原件的事实；日记、对话原话、交易、付款和续费不会在后台自动执行。“实用工具 → 异常雷达”用于查上次结果、下次计划、缺少条件和失败原因。

完整任务清单、首次启用顺序、Mac `launchd` 原则和排障见 [[后台服务与自动化任务]]。

## 八、晚上：日记与日志是两条线

### 日记模式

清洁版不包含内置聊天。晚上可以在手机 GPT 中说“日记模式”，通过 GPT Live 自然聊当天发生的事、感受和想法。

如果配置了 Infans 只读 MCP 插件，手机 GPT 可以在同一个聊天里先按需读取近期日记、当前项目和临近日程，再进入 GPT Live；这个插件只负责读取，不能修改 Studio。结束后把完整对话或固定交接交给本地 AI Agent，由本地 Agent 去重、归档和写回。

本地 Agent 分别处理：

- `10_日志/对话日志/YYYY-MM-DD.md`：保留双方顺序和可读取原话。
- `10_日志/日记/YYYY-MM-DD.md`：仅在用户要求形成日记时，提炼事实、感受、决定与未决事项。
- `30_事业顺利/.../项目进度与待办.md`：只写已经确认且真正改变项目状态的事实。

凌晨 2 点以前的连续夜间对话可以归到前一天；2 点以后归到当天。工作台“实用工具 → 对话日志”是阅读入口，不是聊天入口。

### 项目工作日志

项目日志记录“今天推进了什么、改了哪些原件、验证结果、是否待验收、还剩什么”。有实际施工的 AI Agent 应在阶段结束自动沉淀，不需要用户每次再提醒“写日志”。

日记是生活与感受，项目工作日志是施工与证据，对话日志是原始交流顺序；三者互不替代。

## 九、GPT + AI Agent 的常用方法

### 项目推进

可以先在 GPT 中讨论方向、选项和文案，再把确认后的目标交给本地 AI Agent。用户只需说明项目、需求、不能动的范围和怎样算满意；Agent 自行处理任务与功能关系。

### 专题学习

从专题研究选择一个知识节点，让 GPT 围绕节点讲解；本地 AI Agent 负责检查来源、去重和学习状态。灵感可以关联事业项目，但不会未经确认自动变成项目任务。

## 十、其他项目怎样连接到事业顺利

### 项目资料就在 Studio 内

复制 `90_使用说明/模板/事业项目模板/`，填写稳定 `projectId`，再把项目登记到 `30_事业顺利/事业顺利_总览.md`。

### 项目工程在 Studio 外

1. 外部工程根目录放置 `.infans/project-hub.v1.json`，可复制 `90_使用说明/模板/外部项目接入/`。
2. 清单只暴露项目名、状态、工作线、功能树和相对 Markdown 来源；禁止指向密钥、构建目录和工程外文件。
3. 复制 `00_本地工作台/project-sources.example.json` 为 `project-sources.local.json`。
4. 在本机配置中用同一个项目 ID 登记外部工程绝对目录。
5. 在 `事业顺利_总览.md` 登记同一个项目 ID 和 Studio 内的项目管理原件。
6. 点击刷新圆圈；事业页会读取外部 `.infans` 薄清单，真实项目文件仍留在外部工程。

`project-sources.local.json` 已被 Git 忽略，不应分享。对方 Mac 上的路径必须由对方自己填写。

## 十一、需要准备的支持项

### 必需

- `Infans_Studio` 与 `Infans_Support` 同级。
- Node.js、pnpm、可用浏览器。
- 一套可恢复的备份。

### 推荐

- Obsidian：打开 Markdown 原件，资料库名使用 `Infans_Studio`。
- 本地 AI Agent：项目工程修改、任务登记、原件核验、日志沉淀、构建与浏览器验收。
- macOS 后台服务与周期任务：先按 [[后台服务与自动化任务]] 启用本机服务和每日日志收口，其他任务按需增加。
- Infans 只读 MCP 插件：让手机 GPT / GPT Live 读取必要的本地上下文；它不提供写入能力，需按个人环境另行搭建和验收。
- Safari Web App：Mac 独立窗口和 iPhone 主屏幕体验。
- 私人网络工具：用于不公开暴露服务的手机访问，按个人设备环境自行选择。

### 按需

- 外部项目的 `.infans/project-hub.v1.json`。
- 本机 `project-sources.local.json`。
- 自己的音乐文件：放进 `Infans_Support/20_媒体/音乐示例/` 或另设本地目录。
- 资产、健康、日历真实数据接入：当前只展示界面和假数据，必须单独设计隐私与备份后再开。

## 十二、不要误解的地方

- 刷新不会把 GPT 对话自动写进资料库。
- 工作台卡片是派生视图，不是第二份原件。
- 手机主屏幕图标不代表离线可用。
- Safari Web App 不会自己启动后端服务。
- 异常雷达里的示例任务不等于这台 Mac 已安装后台执行器。
- 演示资产和市场数值不是投资建议，也不是实时账户数据。
- 清洁版没有聊天、多人会话、自动备份或真实账号连接；只读 MCP 说明是搭建方法，不代表已经替对方连接完成。
