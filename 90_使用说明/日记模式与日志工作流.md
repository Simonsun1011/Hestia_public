# 日记模式与日志工作流

## 四种东西分别解决什么

| 内容 | 解决的问题 | 原件位置 |
|---|---|---|
| 日记模式对话 | 当时是怎样想、怎样说的 | 外部 GPT / GPT Live，对话后交给本地 AI Agent |
| 对话日志 | 哪些原话值得按顺序长期保留 | `10_日志/对话日志/YYYY-MM-DD.md` |
| 日记 | 今天发生了什么、感受如何、做了哪些决定 | `10_日志/日记/YYYY-MM-DD.md` |
| 项目进度 | 某个事业项目现在的真实状态 | `30_事业顺利/项目名/项目进度与待办.md` |

## 最省事的用法

1. 对 GPT 说“日记模式”，自由说当天的事。
2. 结束时让 GPT 先列出事实、感受、决定、待确认和项目关联，但不要让它声称已经写入。
3. 把完整对话交给本地 AI Agent。
4. AI Agent 先按来源会话与日期去重，再保存对话日志；只有用户要求时才继续提炼日记。
5. 只有明确改变项目状态的内容才写回项目原件。
6. 打开“实用工具 → 对话日志”和“工作日志”检查结果。

## 对话日志保留什么

- 双方说话顺序。
- 真正影响理解、决定或后续的原话。
- 时间分隔与主题分隔。
- 必要的上下文，不补写没说过的话。

账号、密码、一次性验证码、银行卡资料和不希望长期保存的附件不要归档。

## 日记保留什么

- 今天实际发生的事情。
- 当时感受与身体状态。
- 已确认的决定。
- 仍不确定的判断。
- 明天可能继续的事情，但不把可能写成承诺。

## 工作日志保留什么

工作日志偏结果：推进了哪条任务、改了什么原件、形成了什么证据、哪些检查通过、是否待验收、还剩什么。它适合回顾工程和项目推进，不替代情绪与生活日记。

有实际施工的 AI Agent 应在阶段结束自动完成两件事：

1. 更新所属项目的当前状态、任务、阻塞、最近完成与下一步。
2. 在项目 `20_记录/` 或中央工作日志留下本次推进短记录。

用户不需要每次另外说“写日志”。“写个总结”仍只表示在对话中总结；“写今天的日志”才表示汇总当天跨项目工作。

## 只读 MCP 怎样帮助手机日记

可以另建一个 Infans 只读 MCP 插件，让手机 GPT 在获得授权后读取近期日记、当前项目、待办和临近日程，再在同一个聊天里启动 GPT Live。

正确链路是：

```text
手机 GPT 只读资料 → 同一聊天进入 GPT Live → 输出交接
→ 本地 AI Agent 核验、去重和写回 → 工作台阅读
```

只读 MCP 不提供创建、修改、删除和命令执行，因此 GPT Live 不能声称已经写入 Studio。Mac 离线、插件不可用或必要原件没有读到时，应明确降级为无上下文聊天，不能靠模型记忆补故事。

搭建与验收方法见 `外部AI只读MCP与手机工作流.md`。

## 常用交接话术

```text
这是今天的日记模式完整对话。请先按原顺序保存对话日志；只有我明确要求时再提炼日记。
项目事实按项目分别处理；建议和推测不要写成已决定。不要保存秘密或不希望长期保留的附件。
```

```text
这是一次项目讨论，不写整天日记。只把已经确认的结论写回指定项目，并在工作日志留下本次推进与验证。
```
