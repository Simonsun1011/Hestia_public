# 个性化与支持项准备

## 建议顺序

1. 改称呼、时区和首页问候。
2. 用自己的一个真实项目替换一个演示项目。
3. 建立日记与日志习惯。
4. 接入日语或一个专题学习主题。
5. 配置 Safari Web App、工作台常驻服务和备份。
6. 试跑每日日志收口，再按需增加其他自动化。
7. 最后才考虑健康、资产、手机远程访问和外部项目。

不要第一天就把所有演示数据删空。一次替换一个模块，每次确认工作台还能读取。

## 资料准备

- 事业：项目名、稳定 ID、当前状态、正在做、下一步、阻塞、最近完成。
- 日程：哪些任务需要日期，哪些只是长期主线。
- 学习：目标级别、教材、知识节点、复习证据。
- 日记：对话日志与日记各自的保存边界。
- 馆藏：标题、类别、状态、封面来源和个人判断。
- 资产：只有决定在本机私用后才准备；永远不要放密码、PIN、CVV 或完整银行卡号。

## 工具准备

- Obsidian：建立名为 `Infans_Studio` 的资料库。
- 本地 AI Agent：把 Studio 根目录保存为项目，先读 `AGENTS.md`，确认它能读取原件、登记任务、运行检查并回写项目日志。
- Safari：添加到程序坞；手机端添加到主屏幕。
- 私人网络：只在需要手机长期访问时配置，选择适合自己设备的方案，不要公开暴露本机服务。
- 只读 MCP 插件：需要手机 GPT / GPT Live 读取本地资料时另行搭建；保持只读，由本地 AI Agent 负责正式写回。
- 外部项目：各自提供 `.infans/project-hub.v1.json` 与相对 Markdown 原件。
- 后台任务：读 [[后台服务与自动化任务]]，先审核将要安装的登录项、时间、读写路径和日志路径；手动试跑和定时自然触发都要验证。

## 支持库职责

Support 放体积大、可替换、不是知识原件的内容：封面、音频、导出后的公共参考资料。Studio 放索引、说明、项目事实和工程。两者保持同级，备份时一起复制。

## 个性化后再分享

一旦填入真实日记、资产、健康或项目资料，就把它视为新的私人版本。以后要再次分享，应重新从纯清洁版复制，不要在私人版本里临时删除几处就发出去。

## 安全与隐私需要拥有者亲自复核

清洁版的规则只能提供通用建议：秘密与身份资料不要进入知识库和日志，外部连接使用最小权限，分享前重新检查个人、财务、设备、网络与第三方资料。

请由本项目拥有者重点审核这一部分。每个人的资料敏感度、设备、账号、备份和分享对象不同，需要酌情决定哪些内容保留、排除、加密或完全不接入。
